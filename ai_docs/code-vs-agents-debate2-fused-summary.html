Executive Summary — Both Sides of the Argument Fused

The Architect's case

Deterministic code should be the backbone, and agents should earn every node they occupy. Reliability degrades as probabilistic decisions compound, while code makes exact mechanics reproducible, testable, auditable, and cheap to run.

Code should own identity, permissions, secrets, durable state, budgets, retries, idempotency, audit logs, and irreversible effects. Agent costs extend beyond tokens: evaluation maintenance, silent semantic errors, prompt coupling, behavioral drift, and vendor-forced model migrations all matter.

For recurring, consequential systems, begin with a code-first prior. As agent behavior stabilizes, harvest exactly specified mechanics into code and leave agents only where interpretation, synthesis, or adaptive investigation remains necessary.

The Builder's case

Code-first becomes dogma when determinism is confused with correctness. A deterministic classifier can be reproducibly wrong; a cheap rule with poor recall is not superior to a model whose higher quality avoids expensive mistakes.

The objective is not minimum stochasticity but minimum total expected lifecycle cost at the required quality and safety. Use four tiers: deterministic code for exact mechanics, heuristics or specialized models for stable narrow prediction, bounded agents for open-ended adaptive work, and humans for high-consequence judgments that cannot be reliably validated.

Generation and acceptance are separate. Code may verify a patch that an agent is best equipped to generate. Agents can search, debug, investigate, and explore inside a sandbox while code controls tools, time, permissions, state, and final acceptance.

Where the debate converged

Both sides rejected the monolithic production skill where one agent owns planning, orchestration, policy, execution, and approval. The shared architecture is a deterministic control plane around the smallest adequate stochastic core: code owns authority; agents own bounded interpretation and adaptive work; independent checks or humans own acceptance.

When a property can be checked exactly, code checks it. Generation is selected economically by comparing code, heuristics, specialized models, agents, and humans against pre-registered quality, latency, privacy, cost, and maximum-loss thresholds.

The remaining disagreement is the default before measurements exist. The Architect leans toward code as recurrence and blast radius rise because agent lifecycle costs are harder to forecast. The Builder applies the same risk premium proportionally, resisting a universal code-first veto for low-risk, novel, reversible work.

The Question

"Agents plus code beats agents alone and code alone — but how should work be separated? The 'agentic' approach throws everything into a single skill/agent. The 'code' approach builds a deterministic pipeline and uses agents only for what code can't do. How should we best use agents+code, and how much should we lean on code alone?"

Bottom Line — The Answer That Survived Both sources agree

Neither pure approach survived, and the monolithic "one big skill" lost unanimously for recurring production work. The winning shape is a deterministic control plane around the smallest adequate stochastic core Builder — expressed as a six-step decision procedure Architect:

  1. Code owns the control plane, always. State, routing, retries, budgets, authorization, irreversible effects, and final acceptance live in deterministic code. Agents live inside nodes of a code-owned graph — never as the top-level architecture.
  2. Allocate each node across four tiers — deterministic code, small/specialized model, bounded agent, human — choosing the cheapest tier that meets pre-registered quality, latency, and risk thresholds, costed by total lifecycle cost.
  3. Run the assertion test — but only for acceptance. If a checkable acceptance predicate exists, code does the accepting, never the agent grading itself. If the entire behavior is assertable (parsing, validation, state machines, iteration), code implements it outright: code hits the 100% ceiling and nothing stochastic beats a ceiling.
  4. Size agent work at natural semantic units. One call per judgment; a bounded multi-turn loop (code-owned budget & termination) for exploratory nodes like debugging or incident investigation. Never shard a summary into paragraph calls; never make an LLM re-enact a for loop.
  5. Ratchet as you learn. Harvest stable mechanics (routing, formatting, escalation policy, validation) into code over time. One-way for assertable mechanics; bidirectional for semantic cores as models and input distributions change.
  6. When no benchmark data exists yet, lean code in proportion to recurrence × blast radius. Prototypes and low-stakes tools go agent-first; payments, migrations, and high-volume recurring flows go code-first, with agents earning each node.
Practical rule Builder: code owns authority, state, budgets, validation, and irreversible effects; agents own bounded semantic judgment and adaptive tool use; humans own consequential decisions that cannot be reliably checked.

Opening Positions Architect

ARCHITECT — Round 1

Code is the backbone; agents are narrow, schema-bounded components used only where judgment, ambiguity, or unstructured input make code impossible. Key arguments: multiplicative reliability (five 99.9% stages ≈ 99.5% end-to-end vs. one agent doing five implicit 95% steps ≈ 77%); code is where testing/regression control live; token cost curves; small clean contexts help the agent itself; a one-way ratchet harvesting agent solutions into code.

BUILDER — Round 1

Code-governed, agent-assisted: code owns control flow, state, permissions, validation, irreversible effects; agents get bounded decisions whose specs can't be encoded economically. Boundary = "uncertainty vs. authority"; pattern = "agent proposes, code disposes." Cited SWE-agent (2.80% → 12.47% on SWE-bench via interface design) and Agentless (27.33% on SWE-bench Lite via explicit decomposition).

Notable: both agents converged on rejecting the monolithic single-skill approach in Round 1. The real debate became where the boundary sits, what rule sets it, and which way it moves.

Load-Bearing Arguments That Survived Architect

  • Multiplicative reliability, at matched adequacy. 0.9995 ≈ 0.995 vs 0.955 ≈ 0.774. Scoped by BUILDER's correct objection: adequacy is checked first; minimizing stochastic surface is the tie-breaker among adequate options, not the objective.
  • Assertable-task dominance. For behaviors with a checkable spec, code reaches the quality ceiling; a stochastic component at best ties on quality and must lose on cost, latency, and audit. The mechanics ratchet is one-way as dominance, not empirical bet — with a stated, unmet falsification condition.
  • The verification-regime gap. Per-instance checks of encoded properties: ~zero marginal cost, instant, loud. Statistical evals: labeled datasets, real dollars per run, lagging detection. (Scoped to encoded properties per Dijkstra's caveat: tests show presence, not absence.)
  • The variance asymmetry. Agent-path cost terms (P(error), maintenance, silent-error loss) carry higher estimation variance — CACE/entanglement (Sculley et al. 2015) plus vendor-scheduled model deprecations. Optimizing under asymmetric variance means biasing the default toward the estimable option: code.
  • Architecture scoping of the evidence. Anthropic's workflow/agent guidance selects which nodes get autonomous loops ("steps cannot be predicted"), not which architecture wins; SWE-agent's 2.80%→12.47% shows interface quality matters inside a bounded loop. Both support a code-owned graph with autonomy inside nodes.

A Runnable Decision Procedure Builder

BUILDER's answer to ARCHITECT's "factor list isn't a procedure" charge: make allocation falsifiable by setting thresholds before comparing implementations.

  1. Set acceptance thresholds. Pre-register required quality, latency, privacy, cost, observability, and maximum-loss limits.
  2. Hard-gate authority. Keep identity, authorization, durable state, and irreversible effects in deterministic code or accountable human review.
  3. Build the cheapest credible baselines. Compare a deterministic rule or solver, a specialized model, and a bounded agent where each is viable.
  4. Reject inadequate candidates. A nearly free regex with unacceptable recall is not cheaper; it is disqualified.
  5. Price the entire lifecycle. Include implementation, inference, evaluation, maintenance, vendor migration, detection lag, and expected error loss.
  6. Deploy reversibly and re-evaluate. Use replay or shadow traffic first, monitor drift, and rerun the comparison when models, data, or requirements change.
Default before data Both converged: choose code-first for recurring, consequential operations; choose agent-first for novel, reversible experiments. The prior scales with recurrence × blast radius.

Honest Concessions Ledger Architect

ARCHITECT conceded:

  • Dropped "Agents only where code is impossible." Wrong boundary — it's lifecycle economics ("cheapest adequate"), not possibility. BUILDER was right from Round 1.
  • Dropped "Only code has testing/debugging." Statistical evals, replay, shadow traffic are real. The regime gap survives; the "only" did not.
  • Dropped "One hard sub-problem per call." Exploratory work (debugging, incident investigation) needs bounded multi-turn loops.
  • Withdrawn The causal leaderboard claim ("agentic scaffolds decisively overtook Agentless") — uncontrolled comparison; all benchmark evidence exited as proof of universal law, from both sides.
  • Demoted Minimize-stochastic-surface as objective → tie-breaker. A deterministic rule wrong 20% of the time loses to a model wrong 3%.
  • Scoped Universal burden of proof on agents → burden scales with recurrence × blast radius; prototypes rationally start agent-first.
  • Narrowed The ratchet: one-way for assertable mechanics only; semantic implementations may move either direction.

BUILDER conceded symmetrically:

  • SWE-agent over-attribution (it's an autonomous loop, not deterministic orchestration).
  • Validation insufficiency: "agent proposes, code disposes" is necessary, not sufficient.
  • Pipelines/small models win stable high-volume work.
  • Its production prediction lacked evidence; SWE-bench can't carry it.
  • Shrink ≠ shard; token price alone never justifies de-codifying correct deterministic code.
  • Code-owned top level.

Agreements & the Live Disagreement Fused

What survived as agreement Builder

  • Code owns the top-level control plane.
  • Agents can own multi-turn exploration inside bounded nodes.
  • Assertions and tests accept outputs where they encode the requirement.
  • Plausible-but-wrong semantic output requires evaluations or people, not schemas alone.
  • Stable mechanics should be harvested into code.
  • Learned systems incur evaluation, drift, and provider-migration costs.
  • High-volume narrow prediction may belong to a specialized model, not a general agent.

What remains disputed Builder

  • Default burden: universal code-first versus a prior scaled to consequence and reversibility.
  • Assertion scope: whether lack of a per-instance predicate should prohibit deterministic semantic heuristics.
  • Estimation risk: whether agent lifecycle costs are universally less estimable or only workload-dependent.
  • Boundary direction: exact mechanics move one way into code; recurring semantic implementations may still move either way.
ARCHITECT holds

Most boundary decisions happen before benchmarks are affordable. There, the default must lean code for recurring, consequential work — because the agent path's cost terms carry provably higher estimation variance (CACE, vendor-scheduled change). And the ratchet is one-way for assertable mechanics as a matter of dominance.

BUILDER holds

No universal code-first prior and no one-way semantic ratchet: the objective is expected harm-adjusted lifecycle performance; the prior should vary with blast radius, volume, novelty, and reversibility; allocation should be settled per-workload by pre-registered benchmarks, and even mechanics stay open to re-benchmarking as model reliability improves.

What would settle it Architect Builder: matched-quality production A/Bs on recurring workloads over 18–24 months including at least one forced model deprecation or material requirement change — tracking engineering time, incidents, silent-error detection delay, latency, evaluation maintenance, and migration cost. For the ratchet: a single documented case of teams rationally replacing working parsers, checksums, or state machines with LLM calls. If that case surfaces, the one-way ratchet breaks.

Production Checklist Builder

If an agent node cannot satisfy these controls, it is still a prototype.

  • Named owner and bounded business purpose
  • Scoped inputs and deliberate context selection
  • Least-privilege, allow-listed tools
  • No direct ownership of secrets or authorization policy
  • Token, time, iteration, and spending budgets
  • Typed outputs where structure is knowable
  • Runtime assertions for exact invariants
  • Held-out semantic evaluation for judgment quality
  • Human approval for unassertable high-loss effects
  • Idempotency and safe retry behavior
  • Complete trace and model/prompt version records
  • Fallback, escalation, and kill switch
  • Shadow deployment before consequential authority
  • Drift and incident monitoring
  • Provider migration plan
  • Periodic review for mechanics to extract into code

Evidence Discipline Builder

The debate referenced SWE-agent, Agentless, and Sculley et al.'s Hidden Technical Debt in Machine Learning Systems. The final position uses them only for their narrow lessons: interfaces matter, explicit decomposition can be viable, and learned systems introduce distinctive technical debt. It does not treat benchmark leaderboard results as proof of a universal production architecture — a discipline both sides ultimately enforced on each other Architect: withdrawn leaderboard claim Architect: SWE-bench scoping of BUILDER's citations.

Bottom line: lean heavily on code for authority and stable mechanics; lean on agents for bounded, reversible work where semantic flexibility earns its lifecycle cost.
