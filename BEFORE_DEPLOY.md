# Before Deploy

Boiling this repo down to the distributable artifact: **`.claude/skills/sssf/` alone.**

Everything else here is stamped output or evidence that the skill works. It earns its place in the video and in this repo; it does not belong in the thing someone installs.

**Status 2026-08-02: the split is done.** `main` is the skill alone; this `example` branch is `main` plus everything else, and it is the deletion commit reverted — so `git merge main` brings skill updates forward without replaying the deletion. What remains open is §1 and the tail of §5/§6.

---

## 1. Blockers — the skill is not self-sufficient until these are fixed

Still open, all three. Each is now a row in `main`'s README failure table, so nobody is surprised by one — but documenting a gap is not closing it.

- [ ] **`install.py` never stamps a `justfile`.** It stamps `templates/adws` → `adws/`, `templates/prompt_engineering`, `templates/harness_engineering`, `templates/sssf.config.yaml`, and `templates/env.sample`. Meanwhile five files inside the skill tell the orchestrator to run `just` recipes: `run_adw.md` (`just phases|procs|kill|rosters`), `how_to_prompt_for_the_eng.md`, `sssf_overview.md`, `update_config.md`, `update_modules.md`. **A freshly stamped repo gets the instructions without the commands.** Pick one:
  - add `templates/justfile` and stamp it (recommended — the recipes are part of the operating experience, and this branch's `justfile` is the obvious starting point), or
  - rewrite those cookbook references to the raw `uv run` / `sqlite3` forms and treat `just` as a convenience this repo happens to have.

  `main`'s README already takes the second posture for the *engineer* — every recipe is shown in its raw form there. The five cookbooks that instruct the *orchestrator* were not touched.
- [ ] **Verify a clean stamp end to end.** `git init` a scratch dir, copy `.claude/skills/sssf/` in, run `uv run .claude/skills/sssf/scripts/install.py`, then `uv run adws/adw_prompt.py "ping"`. This has never been tested from a bare directory — only against this repo, which already had everything. Highest-value item left: it is the exact path every new user walks.
- [ ] **Replace the placeholder quality blocks or make the failure loud.** `templates/adws/adw_modules/quality.py` ships `echo PLACEHOLDER…` commands that exit 0. Three stamped ADWs (`adw_build_test`, `adw_plan_build_test`, `adw_simple_sdlc`) run them as their test phase, so a fresh install reports green tests it never ran. The banner says so in a comment; the run does not.

## 4. What happened to the demo material — DECIDED 2026-08-02

They stay, on this branch, and this branch is not the distribution.

- [x] `adws/` — stamped output, kept here so a reader sees a real populated factory.
- [x] `apps/inkwell/` — the app the factory built, tested, reviewed, and documented. The proof.
- [x] `specs/` and `app_docs/` — real artifacts from real runs. The README now says so explicitly, because "an agent wrote this, during a run, named for the run" is the whole point of showing them.

It stays a local artifact. Revisit only if the mocks need to be public, and then put them somewhere that is not a git object.
- [x] `ai_docs/` — the code-vs-agents debate notes behind the doctrine. Kept.
- [x] `VALUE.md` — kept on this branch, off `main`. It is positioning, not product.
- [ ] `requests/` and `tmp/` at the repo root — `requests/` is tracked and holds real ADW prompts, so it reads as evidence and stays; `tmp/` is empty and untracked. Delete it or ignore it.

## 5. Distribution mechanics

- [x] **How does someone get the skill?** Two branches in one repo. `main` is the skill alone — clone it, or copy `.claude/skills/sssf/` out of it into a target repo. `example` (this branch) is the same skill with a factory stamped in, for reading rather than installing. One URL, one issue tracker, and the example cannot rot into a fork, because skill work only ever happens on `main` and merges forward.
- [x] **Where does the visualizer live?** Inside the skill (`apps/visualizer`), shipping with it. Its `src/lib/` being gitignored mattered and was fixed on 2026-07-29; `git ls-files .claude/skills/sssf` now covers everything it needs to compile.
- [ ] **Version the skill.** Nothing in `SKILL.md` states a version, so a stamped repo cannot tell which vintage it came from, and `install.py --force` cannot warn about a downgrade. Unblocked, and worth doing before the first real user.
